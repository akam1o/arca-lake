# Development archive

Historical records explain how the project reached its current design.
They retain their original claims, dates and verification limits; they are
not current configuration instructions or a release-readiness assessment.

| Record | Scope |
| --- | --- |
| [Pre-release changelog](pre-release-changelog.md) | Complete phase-by-phase changelog through `ab19a586`, preserved when the root changelog was condensed |

Earlier phase plans remain at their original paths to preserve references;
the [roadmap index](../roadmap/README.md) separates them from active work.
The [initial design analysis](../architecture/design-decisions.md),
[technology survey](../architecture/technology-selection.md), and
[initial decision backlog](../architecture/open-decisions.md) remain at
their original paths and are labelled as historical.
ADRs and verification reports stay in their existing locations
because they explain decisions and provide evidence for current behavior.

Start with the [documentation index](../README.md) for current guides,
architecture, compatibility and limitations. Use the
[current changelog](../../CHANGELOG.md) for a concise view of changes.
